# 開発環境管理ツール ロードマップ

## 1. 目的

v1で提供するローカルPC上の単一利用者向けDockerコンテナ管理を基盤として、社内の複数開発者が安全に利用できる形へ段階的に拡張する。本書は優先順位と方針を示す可変の計画文書であり、確定した機能要件は別途要件定義書に記載する。

## 2. 優先順位

### v1.1: 社内共有の安全な基盤

- 既存のIdPとOIDCで連携するログイン機能を追加する
- アプリケーション内で利用者のパスワードは保持しない
- 未認証の利用者は、画面閲覧およびAPI呼び出しを実行できないようにする
- TLSによる通信暗号化を必須とし、社内ネットワークからのアクセスに限定する
- DockerソケットおよびDocker Engine APIを外部へ直接公開しない
- 管理対象は共有する開発用Dockerホスト1台とし、本番Dockerホストは対象外とする

### v1.2: ロールと監査

- 利用者に次のロールを割り当てる
  - 閲覧者: コンテナ状態、詳細、ログ、履歴を参照できる
  - 操作者: 閲覧者の権限に加え、起動・停止・再起動を実行できる
  - 管理者: 操作者の権限に加え、利用者とホスト設定を管理できる
- 権限はDockerホスト単位で設定できる設計にする
- 操作履歴に、実行者、認証主体、対象ホスト、日時、操作、結果、結果メッセージを記録する
- 管理者は操作履歴を利用者、対象、期間、結果で検索・絞り込みできるようにする

### v1.3: 運用性の強化

- 操作履歴をCSV形式で出力できるようにする
- 操作履歴の保存期間を設定できるようにする
- Docker接続障害、Docker操作失敗、認可拒否を区別して画面表示および履歴記録する
- 管理者がDockerホストの接続状態と直近の失敗操作を確認できるようにする

### v2以降: 複数Dockerホスト

- Dockerホストの登録、切替、接続状態の一覧表示を追加する
- ホストごとに利用者・ロールの操作権限を設定できるようにする
- リモート接続は安全なエージェントまたは相互TLSで保護したAPIを利用する
- 無保護なリモートDocker Engine APIの公開は行わない

## 3. 主要なインターフェース変更

- 既存のAPIはすべて認証を必須とし、認証主体とロールに基づいて認可する
- 操作履歴のデータには、実行者、認証主体、対象ホスト、認可結果を追加する
- 管理者向けに、Dockerホスト設定、ロール割当、監査履歴検索のAPIと画面を追加する
- OIDCの接続情報は環境変数またはデプロイ設定から注入し、特定のIdPに依存しない

## 4. テスト方針

- 未認証、閲覧者、操作者、管理者の各状態で、画面とAPIの認証・認可を検証する
- 操作履歴に実行者、対象ホスト、成否が永続化され、検索およびCSV出力の結果と一致することを検証する
- TLSとアクセス制限を有効にした構成でのみサービスを公開し、Dockerソケットが外部公開されないことを確認する
- Docker接続障害、IdP障害、認可拒否時に、安全なエラー表示と監査記録が残ることを検証する

## 5. 前提

- 利用は社内ネットワーク内の開発用途に限定する
- 組織の既存IdPは標準OIDC連携を提供できるものとする
- 初期の共有対象Dockerホストは1台とする
- v2の対象範囲と受け入れ基準が確定した時点で、必要に応じて `docs/task_v2.md` を作成する
