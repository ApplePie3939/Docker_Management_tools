# 開発環境管理ツール メモ

## 目的

Web画面から開発用Dockerコンテナの状態を確認し、起動・停止などの基本操作を行えるようにする。
ローカルPC上のDocker Engineを管理対象とし、開発環境をコマンド操作なしで扱いやすくする。

## 想定する利用者

- 複数の開発環境を使い分ける開発者
- Docker操作に慣れていないメンバー

## 初期機能

- Dockerデーモンに接続できるかを画面で表示する
- コンテナ一覧を表示する
  - コンテナ名、イメージ名、状態、公開ポートを確認できる
- コンテナを起動・停止・再起動する
- 必要に応じてコンテナを作成／削除する
- 操作結果とエラー内容を画面に表示する

## 管理対象

- Dockerコンテナ
- コンテナに紐づくイメージ、ボリューム、ネットワークは、まず参照中心とする
- Docker Composeで定義された開発環境の起動・停止は将来的な拡張候補とする

## Web画面のイメージ

- ダッシュボード: Dockerの接続状態と、起動中・停止中コンテナの件数
- コンテナ一覧: 状態で絞り込み、各行から起動・停止・再起動を実行
- コンテナ詳細: 環境変数、ポート、マウント、ログなどを確認
- 操作履歴: いつ、どのコンテナに、どの操作をしたかを確認

## 技術的な考え方

- WebアプリのバックエンドからDocker Engine APIを利用してコンテナを操作する
- バックエンド自身をDockerコンテナとして動かす場合は、Dockerソケットまたは安全に構成したAPI経由でDocker Engineへ接続する
- Docker操作の権限は強力なため、アクセスできる利用者・操作対象を制限する
- 開発環境向けを前提とし、本番環境のDockerホストを直接管理対象にしない

## 非機能・安全面

- 操作前に対象コンテナと実行内容を明確に表示する
- 削除など破壊的な操作には確認画面を設ける
- 操作ログを残す
- Docker接続エラーや操作失敗時に、次に確認すべき内容を案内する

## 今後決めること

- 管理対象はローカルDockerのみか、複数ホストも扱うか
- Docker Composeプロジェクトを最初から管理対象に含めるか
- 認証（単一ユーザー／ログイン機能）の要否
- コンテナ作成画面で設定できる項目の範囲
- 採用するフロントエンド・バックエンド技術
